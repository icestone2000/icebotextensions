# 轮胎报价查询工具使用说明

`tire_price_query` 是一个扩展工具：客户在微信 / 企业微信 / 闲鱼里问轮胎价格时，机器人从 Excel 价格表中按 **品牌 + 型号 + 报价类型** 查到报价，按你定义的格式排好版，直接发给客户。

价格表由业务人员在 Excel 里维护，**改完存盘即生效，不用重启机器人，也不用改任何代码**。

扩展源码：[extensions/tire_price_query/](../extensions/tire_price_query/)

---

## 一、先看一眼效果

客户发：

```text
马牌 205/55R16 多少钱？
```

机器人发出（格式由你在提示词里定义）：

```text
马牌 205/55R16 A类报价：520元
马牌 205/55R16 防爆胎 A类报价：780元
```

客户没说品牌时（`品牌` 不传，返回全部品牌）：

```text
马牌 205/55R16 A类报价：520元
马牌 205/55R16 防爆胎 A类报价：780元
米其林 205/55R16 A类报价：610元
普利司通 205/55R16 A类报价：570元
邓禄普 205/55R16 A类报价：490元
```

## 二、第一步：准备价格表

### 2.1 文件放哪里

价格表文件名为 **`轮胎型号.xlsx`**，放在 **机器人程序所在目录**（开发环境为 `backend/` 目录，打包后为 `.exe` 所在目录），与 `快递价格表.xlsx` 同一位置。

如果要同时维护多张表（例如不同区域、不同渠道），可以再放几个文件，调用时用 `price_table_filename` 参数指定文件名即可，例如 `轮胎型号_华东.xlsx`。

> 扩展目录里附带了一份空白模板 [`轮胎型号.xlsx`](../extensions/tire_price_query/轮胎型号.xlsx)（446 行常见品牌 + 规格已填好，报价列留空），复制到上述目录后照着填价就能用。

### 2.2 表结构

只取 **第一个工作表**，第 1 行是表头，从第 2 行开始是数据：

| 品牌 | 规格 | 备注 | A类报价 | B类报价 | C类报价 |
|------|------|------|--------|--------|--------|
| 马牌 | 205/55R16 |  | 520 | 570 | 620 |
| 马牌 | 205/55R16 | 防爆胎 | 780 | 850 | 930 |
| 米其林 | 205/55R16 |  | 610 | 670 | 730 |
| 普利司通 | 235/60R18 | 特殊花纹 | 面议 | 面议 | 面议 |
| 固特异 | 235/55R19 |  |  | 1250 | 1360 |

表头规则：

| 列 | 是否必须 | 说明 |
|---|---|---|
| **品牌** | 必须 | 列名固定叫「品牌」 |
| **规格** | 必须 | 也可以写成「型号」，两种表头都认。这一列就是客户口中的「型号」 |
| **备注** | 可选 | 如「防爆胎」「静音」「特殊花纹」，用于区分同型号的不同货 |
| **报价类型列** | 至少一列 | **除上面三列之外的所有列，都会被当成报价类型**，列名就是报价类型的名字 |

### 2.3 报价类型完全由表头决定 ⭐

这是最需要理解的一点：**报价类型不是写死在程序里的，而是读表头**。

- 现在表头是「A类报价 / B类报价 / C类报价」，那报价类型就是这三个；
- 明天业务把表头改成「大客户报价 / 小客户报价 / 批发价」，报价类型就自动变成这三个；
- 想加一档，直接在表格右边加一列「活动价」，它立刻就是一个新的报价类型。

**加列、改名、删列都不需要改程序、不需要重启。**

### 2.4 单元格填写规则

| 情况 | 结果 |
|---|---|
| 填数字（520 / 520.5） | 正常显示，整数不带小数点（显示 `520`） |
| 填文字（面议 / 电议） | 原样显示 |
| **留空** | 显示「**暂无报价**」，不会报错，也不会漏掉这条记录 |
| 整行只填了品牌、规格是空的 | 这一行会被忽略 |
| 两行内容完全一样 | 自动去重，只回复一条 |

## 三、第二步：在后台启用工具

1. 进入 **「微信管理」→「系统配置管理」**（企业微信在其对应的系统配置管理页）。
2. 打开 **「启用工具调用功能」** 开关。
3. 点 **「选择工具」**，勾选 **`tire_price_query`**。
4. 点 **「保存配置」**。

> ⚠️ 没勾选这个工具，大模型根本看不到它，提示词写得再详细也不会调用。

## 四、第三步：写提示词（核心）

在 **「聊天配置」→ 编辑 → AI 大模型提示词** 里，把轮胎报价的规则写清楚。系统会自动把工具清单和 JSON 格式说明拼在你写的提示词后面，**你只需要写业务规则**。

### 4.1 最小可用版本

直接复制下面这段，改掉报价类型和格式就能用：

```text
【轮胎报价规则】
1. 客户询问轮胎价格时，调用 tire_price_query 工具查询报价。
2. 必须从客户消息中提取轮胎型号（如 205/55R16、175/65R14）填到 model 参数。
   客户没说型号时，先问客户要型号，不要猜测，也不要调用工具。
3. 客户说了品牌（马牌、米其林等）就填 brand；没说品牌就不要填这个参数，
   工具会自动返回所有品牌的价格。
4. quote_type 固定填 "A类报价"。
5. format_template 固定填："[品牌] [型号] [备注] [报价类型]：[价格]元"
6. 这个工具会自己把报价发送给客户，所以：
   - requires_tool_result 必须为 false；
   - reply_content 里不要重复报价内容，只写一句简短引导语，例如"好的，价格如下"。
```

### 4.2 推荐的完整版本

覆盖了追问型号、区分客户等级、查不到怎么办等情况：

```text
【轮胎报价规则】

一、什么时候调用
客户询问轮胎价格、报价、多少钱时，调用 tire_price_query 工具。
纯咨询安装、库存、保养等问题，不要调用这个工具。

二、参数怎么填
1. model（必填）：客户说的轮胎型号，原样传入，例如 205/55R16、175/65R14、LT265/60R20。
   - 客户没给型号，先回复"请问您需要什么规格的轮胎呢？（例如 205/55R16）"，本轮不要调用工具。
   - 客户型号写得不完整（例如只说 205/55），可以在型号后面加 * 模糊查询，如 "205/55*"。
2. brand（可选）：客户明确说了品牌才填，例如 马牌、米其林、普利司通。客户没说就不填。
3. quote_type（可选）：
   - 普通客户填 "A类报价"；
   - 客户备注或标签里含"VIP"或"大客户"时填 "B类报价"；
   - 客户明确要求"全部价格"时不填这个参数。
4. format_template（必填）："[品牌] [型号] [备注] [报价类型]：[价格]元"
5. 其余参数不要填。

三、回复要求
1. requires_tool_result 固定为 false。工具会直接把报价发给客户，你不要再复述一遍价格。
2. reply_content 只写一句引导语，例如"您好，这个规格的价格如下："，不超过 15 个字。
3. 如果客户只是随口问"轮胎多少钱"没给型号，正常文字回复追问型号即可，不调用工具。
```

### 4.3 三条必须写进提示词的硬规则

| 规则 | 为什么 |
|---|---|
| `requires_tool_result` 必须是 `false` | 工具自己发消息。设成 `true` 会让大模型拿到结果后再回复一遍，客户会收到两条重复的报价 |
| `reply_content` 里不要写价格 | 同上，避免"引导语 + 报价"变成"报价 + 报价" |
| 没有型号就不要调用工具 | `model` 是必填参数，缺了会直接返回参数错误，客户什么都收不到 |

> **补充**：如果某轮确实不需要机器人再说话，可以让 `reply_content` 输出哨兵 `(__0__)`，系统会识别为"无需回复"，只发工具的报价消息。

### 4.4 另一种用法：让大模型自己组织话术

上面是**工具直发**模式（推荐，回复快、格式稳定）。如果你希望机器人用自然语言把报价讲出来，而不是发一张格式化的价格清单，就改成**模型转述**模式：

```text
【轮胎报价规则】
1. 客户问轮胎价格时调用 tire_price_query，参数 send_to_customer 填 false。
2. requires_tool_result 填 true。
3. 拿到工具返回的报价数据后，用口语化的方式讲给客户听，
   一次最多说 3 个型号，并主动询问是否需要预约安装。
```

两种模式的取舍：

| | 工具直发（默认） | 模型转述 |
|---|---|---|
| `send_to_customer` | `true`（默认，可不填） | `false` |
| `requires_tool_result` | `false` | `true` |
| `format_template` | 必填 | 可不填 |
| 优点 | 快、格式统一、价格不会被模型改写 | 话术自然、可结合上下文推荐 |
| 缺点 | 格式死板 | 慢一倍（两轮大模型调用），且模型有改写价格数字的风险 |
| 查不到时 | 客户只收到引导语，收不到"查不到"的说明 | 模型知道没查到，会主动告知客户 |

> 如果你的价格表还没填全、经常查不到，建议先用**模型转述**模式；表填齐了再换回**工具直发**。

## 五、参数详解

| 参数 | 类型 | 必填 | 中文别名 | 说明 |
|---|---|---|---|---|
| `model` | 字符串 | **是** | 型号 / 规格 | 轮胎型号，支持通配符 `*` `?` |
| `brand` | 字符串 | 否 | 品牌 | 不填 = 返回所有品牌 |
| `quote_type` | 字符串 | 否 | 报价类型 | 取值以表头为准；不填 = 返回所有报价类型 |
| `format_template` | 字符串 | 发送时必填 | 格式定义 / 格式 | 单条记录的排版模板，见下一章 |
| `send_to_customer` | 布尔 | 否 | — | 默认 `true`（直接发给客户）；填 `false` 只返回数据 |
| `max_rows` | 整数 | 否 | 最大条数 | 最多回复多少条，默认 **30** |
| `price_table_filename` | 字符串 | 否 | 价格表文件名 | 用别的价格表时填，如 `轮胎型号_华东.xlsx` |
| `recipient_id` | 字符串 | 否 | — | 发给别人而不是当前会话时才填，一般不用 |

中文别名的意思是：大模型如果写成 `{"型号": "205/55R16"}` 也能识别，不会报错。

## 六、格式定义字符串（`format_template`）

### 6.1 它是「一条记录」的模板

`format_template` 描述的是**一条报价长什么样**。查到几条，就按这个模板渲染几次，用换行拼起来。

模板：`[品牌] [型号] [报价类型]：[价格]元`

查到 3 条，实际发出：

```text
米其林 205/55R16 A类报价：610元
米其林 205/55R16 B类报价：670元
米其林 205/55R16 C类报价：730元
```

### 6.2 可用占位符

| 占位符 | 含义 | 示例 |
|---|---|---|
| `[品牌]` | 品牌列 | 马牌 |
| `[型号]` | 规格列（`[规格]` 是同义写法） | 205/55R16 |
| `[备注]` | 备注列，为空时自动省略 | 防爆胎 |
| `[报价类型]` | 表头原文 | A类报价 |
| `[价格]` | 价格，空单元格显示「暂无报价」 | 520 |
| `[序号]` | 第几条，从 1 开始 | 1 |

### 6.3 更多模板示例

**带序号的清单**

```text
[序号]. [品牌] [型号] —— [价格]元
```

```text
1. 马牌 205/55R16 —— 520元
2. 米其林 205/55R16 —— 610元
3. 普利司通 205/55R16 —— 570元
```

**多行卡片**（模板里直接换行，或者写 `\n`）

```text
【[品牌] [型号]】[备注]
[报价类型]：[价格]元
```

```text
【马牌 205/55R16】
A类报价：520元
【马牌 205/55R16】防爆胎
A类报价：780元
```

**极简**

```text
[型号] [价格]
```

### 6.4 两个排版细节

1. **备注为空时整行会被删掉**。例如模板写成三行：

   ```text
   [型号]
   [备注]
   [价格]
   ```

   备注为空的那条记录，中间那行不会变成空行，而是直接消失。

2. **占位符渲染为空时不留多余空格**。`[品牌] [备注] [价格]` 在备注为空时输出 `马牌 520`，而不是 `马牌  520`。

3. **标点前不会留空格**。模板 `[型号] [备注]：[价格]元` 在备注为空时输出 `205/55R16：520元`，而不是 `205/55R16 ：520元`。左括号前的空格会保留，例如 `[品牌] （[型号]）` 仍输出 `米其林 （205/55R16）`。

### 6.5 ⚠️ 单位不要写在 `[价格]` 外面

如果模板写成 `[价格]元`，遇到没填价格的记录就会渲染成「**暂无报价元**」，遇到「面议」会渲染成「**面议元**」。

两个解决办法，任选其一：

- 模板不带单位：`[报价类型]：[价格]`
- 让业务在 Excel 里连单位一起填：单元格填 `520元`

同理，像 `[备注]` 这种**可能为空**的占位符，建议放在行尾、独占一行，或者紧贴在标点前面（`[备注]：`），避免它左右的修饰文字在为空时变成孤零零的残句。

## 七、匹配规则

### 7.1 型号（`model`）

匹配前会**统一去掉空格、全角转半角、字母转大写**，所以 `205/55 r16`、`２０５／５５Ｒ１６`、`205/55R16` 是一回事。

| 写法 | 行为 |
|---|---|
| `205/55R16` | 先精确匹配；精确查不到时，自动退化为「包含」匹配 |
| `LT265/60R20` | 表里是 `LT265/60R20(POR)`，精确匹配不中 → 自动包含匹配 → 命中 |
| `205/55*` | 通配符，`*` 代表任意多个字符 |
| `205/55R1?` | 通配符，`?` 代表任意一个字符 |
| `*` | 匹配全表（会被 `max_rows` 截断） |

### 7.2 品牌（`brand`）

规则与型号一致（精确 → 包含 → 通配符）。**不填就返回所有品牌**。

品牌填错时不会静默返回空结果，而是返回提示，例如：

```text
型号「205/55R16」下未找到品牌「普利斯通」，当前表格的品牌有：马牌、米其林、普利司通、邓禄普、固特异
```

### 7.3 报价类型（`quote_type`）

以表头为准，且允许只写一部分。假设表头是「大客户报价 / 小客户报价 / 批发价」：

| 填什么 | 命中 |
|---|---|
| `大客户报价` | 大客户报价 |
| `大客户` / `大客户价` / `大客户价格` | 大客户报价（自动忽略「报价 / 价格 / 价」后缀） |
| `客户` | **大客户报价 + 小客户报价**（两个都返回） |
| `*批发*` | 批发价 |
| 不填 | 全部三个 |
| `A类` | 查不到，返回："未找到报价类型「A类」，当前表格可选：大客户报价、小客户报价、批发价" |

### 7.4 结果条数上限

一次最多返回 `max_rows` 条（默认 30）。超出时会截断，并在消息末尾自动加一行说明：

```text
（共 114 条，此处只显示前 3 条）
```

不会出现"悄悄少发了几条"的情况。

## 八、完整场景演练

下面是大模型实际应该输出的 JSON（系统会自动解析并执行）。

### 场景 1：客户报了品牌和型号

> 客户：**马牌 205/55R16 多少钱**

```json
{
  "reply_content": "好的，价格如下：",
  "reply_type": "text",
  "requires_tool_result": false,
  "tool_calls": [
    {
      "tool_name": "tire_price_query",
      "tool_type": "data_query",
      "parameters": {
        "model": "205/55R16",
        "brand": "马牌",
        "quote_type": "A类报价",
        "format_template": "[品牌] [型号] [备注] [报价类型]：[价格]元"
      },
      "description": "查询马牌205/55R16的A类报价"
    }
  ],
  "confidence": 0.95
}
```

客户实际收到两条消息：

```text
好的，价格如下：
```

```text
马牌 205/55R16 A类报价：520元
马牌 205/55R16 防爆胎 A类报价：780元
```

### 场景 2：客户没说品牌

> 客户：**205/55R16 的胎什么价**

`brand` 不填即可，工具会把所有品牌都列出来：

```json
{
  "reply_content": "这个规格我们有以下几个品牌：",
  "reply_type": "text",
  "requires_tool_result": false,
  "tool_calls": [
    {
      "tool_name": "tire_price_query",
      "tool_type": "data_query",
      "parameters": {
        "model": "205/55R16",
        "quote_type": "A类报价",
        "format_template": "[品牌] [型号] [备注]：[价格]元"
      },
      "description": "查询205/55R16全品牌A类报价"
    }
  ],
  "confidence": 0.9
}
```

### 场景 3：客户要看所有档位的价格

`quote_type` 整个不填：

```json
{
  "parameters": {
    "model": "205/55R16",
    "brand": "米其林",
    "format_template": "[型号] [报价类型]：[价格]元"
  }
}
```

发出：

```text
205/55R16 A类报价：610元
205/55R16 B类报价：670元
205/55R16 C类报价：730元
```

### 场景 4：客户型号说得不全

> 客户：**205 的胎**

在型号后面加通配符：

```json
{
  "parameters": {
    "model": "205*",
    "quote_type": "A类报价",
    "max_rows": 10,
    "format_template": "[品牌] [型号]：[价格]元"
  }
}
```

### 场景 5：客户没给型号

**不要调用工具**，正常文字回复：

```json
{
  "reply_content": "请问您需要什么规格的轮胎呢？规格可以看轮胎侧面，例如 205/55R16。",
  "reply_type": "text",
  "requires_tool_result": false,
  "tool_calls": [],
  "confidence": 0.9
}
```

## 九、常见问题

**Q：改了 Excel，机器人还在报旧价格？**
A：等 30 秒再问一次。系统每 30 秒检查一次文件是否变动，变了会自动重新加载。另外确认 **Excel 已经保存**（标题栏没有星号），以及改的是机器人目录下那份文件。

**Q：加了一列「活动价」，需要改程序吗？**
A：不需要。存盘后 30 秒内自动生效，`quote_type` 直接填「活动价」即可。

**Q：客户收到了两遍报价？**
A：`requires_tool_result` 被设成了 `true`，或者 `reply_content` 里也写了价格。检查提示词里的第 4.3 节三条硬规则。

**Q：客户只收到"好的，价格如下："，后面没有价格？**
A：说明没查到记录（工具查不到时不会发消息）。可能原因：型号在表里不存在、品牌写错、报价类型写错。查后台日志搜 `[tire_price_query]`，日志里会写清楚匹配了几条、可选的报价类型有哪些。

**Q：价格显示成「暂无报价元」？**
A：模板把单位写在了 `[价格]` 外面，见第 6.5 节。

**Q：客户问了一个很宽泛的型号，机器人发了一大段？**
A：调小 `max_rows`（例如 5），或在提示词里要求模型必须拿到完整型号才查询。

**Q：想让不同的群用不同的价格表？**
A：多准备几个 xlsx 放在同一目录，在各自聊天配置的提示词里写死 `price_table_filename`，例如"查询时 price_table_filename 固定填 轮胎型号_华东.xlsx"。

**Q：怎么确认工具已经装好了？**
A：调用后端接口 `GET /api/tool-calling/tools/tire_price_query`，能返回参数说明就说明已注册；返回里的工具描述会**列出当前表格里真实的报价类型**，可以顺便核对表头读得对不对。

## 十、附录：测试用价格表

扩展目录里附带了一份 **[`轮胎型号_测试.xlsx`](../extensions/tire_price_query/轮胎型号_测试.xlsx)**（5 个品牌 40 行，价格已填好），用于功能验证。里面特意包含了这些情况：

| 数据 | 用来验证 |
|---|---|
| 马牌 205/55R16 两行（一行备注「防爆胎」） | 同型号不同备注 |
| 米其林 205/55R16 重复两行 | 自动去重 |
| 马牌 LT275/55R20(POR) 三列全空 | 显示「暂无报价」 |
| 固特异 235/55R19 只有 A 类为空 | 部分缺价 |
| 普利司通 235/60R18 填「面议」 | 文字价原样输出 |
| 两个 `LT…(POR)` 型号 | 通配符与包含匹配 |

把它复制到机器人程序所在目录（与 `轮胎型号.xlsx` 同级），调用时把 `price_table_filename` 填成 `轮胎型号_测试.xlsx` 即可，不影响正式价格表。
